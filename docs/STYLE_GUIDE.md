# Style Guide

This document codifies the UI direction already established in `AGENTS.md`, `docs/PRODUCT_SPEC.md`, and the live home screen.

## Core Direction

- Prefer quiet, purposeful layouts over dashboard-card patterns.
- Use spacing, alignment, and thin borders before reaching for large surface containers.
- Keep explanatory copy short. Add text only when it clarifies an otherwise unclear action or state.
- Large rounded corners should be used sparingly. Default to sharper radii for dense work surfaces.
- The home page is the reference point for tone: calm, minimal, and operational rather than decorative.

## Surface Rules

- Avoid wrapping every region in a heavy card.
- Favor simple bordered sections, split panels, and hairline dividers.
- Use one strong container only when it meaningfully groups related controls.
- Neighboring sections should align to a shared grid instead of feeling like isolated widgets.

## Copy Rules

- Keep section titles short and functional.
- Do not restate information the UI already makes obvious.
- Use helper text only for setup warnings, unusual behavior, or irreversible actions.
- Settings and troubleshooting surfaces should be especially terse.

## Radius and Borders

- Prefer radii around `0.7rem` to `1rem` for operational screens.
- Avoid oversized soft-card radii as a default.
- Borders should stay neutral and quiet.
- Shadows should be subtle and secondary to layout structure.

## Task Surfaces

- The task vault should feel like a quiet utility workspace, not a marketing page or feature gallery.
- Canonical task editing, today-list curation, and revision history should appear as adjacent work areas, not as stacked oversized cards.
- The daily focus list should stay compact and ordered.
- Backlog browsing should stay present but visually subordinate to active work.

## Color Usage

- Reuse established app tokens and timer palette accents rather than introducing new page-specific color systems.
- Reserve stronger accent colors for actionable states and current focus.
- Error and setup warnings should be visible but not dominate the full screen.
